# موقع محاضرات النحو والصرف — خطة الانتقال الآمن

**الحالة:** المرحلة التحضيرية؛ GitHub Pages القديم يظل شغالًا حتى تأكيد Cloudflare والنظام الجديد.

## 1. Cloudflare Pages

- المشروع يربط نفس مستودع GitHub (يدعم مستودع Private).
- المصدر: GitHub integration؛ فرع الإنتاج `main`.
- Framework preset: None، Build command: فارغ، Build output directory: `site`.
- ستنشر ملفات `site/` فقط؛ ملفات SQL والإدارة المصدرية خارج هذه المجلدات لن تظهر كملفات خام عند الطلب.
- تحقق من رابط `*.pages.dev` قبل تحويل مستودع GitHub إلى Private.
- لوحة الإدارة `https://<site>.pages.dev/admin/` قابلة للوصول شكليًا لأي شخص، لكن الوصول للبيانات ليس كذلك؛ الحماية من RLS وتوثيق المستخدمين.

## 2. قاعدة بيانات منفصلة على Supabase

أنشئ مشروعًا جديدًا **مستقلًا عن مواعيدي**. لا تستخدم مشروع مواعيدي أو بياناته ولا تضف مفاتيح سرية إلى المستودع.

- نفّذ `supabase/migrations/20261105_initial_schema.sql` في المشروع الجديد فقط بواسطة ترحيل قاعدة بيانات معتمد.
- افحص السياسات والجداول باستخدام Security Advisor.
- اختبر الوصول للطلاب والمدفوعات بدور `anon` وتأكد أنه مرفوض.
- اختبر رؤية الزوار للمواعيد والإعلانات المنشورة فقط.
- في Settings > API Keys، خذ **publishable key** فقط وURL المشروع، وضعهما في `site/config.js`؛ المفتاح العام ليس سرًا. لا تستخدم `service_role` أو `secret key` مطلقًا.

## 3. حساب المسؤول

- استخدم Supabase Auth لإنشاء/دعوة بريد المشرف.
- بعد تسجيل المشرف في Auth وتحقق البريد، افتح Auth > Users وخذ UUID الخاص به.
- أضف UUID من SQL Editor الآمن في المشروع الجديد فقط:

```sql
INSERT INTO public.site_admins(user_id)
VALUES ('<actual_authenticated_user_uuid>')
ON CONFLICT (user_id) DO NOTHING;
```

- العضوية لا يمكن لأي مستخدم إضافتها لنفسه عبر المتصفح.
- تأكد من Email Redirect URLs بإضافة رابط `/admin/` الجديد ورابط المعاينة.
- يفضل تعطيل التسجيل العام، واستخدام حساب/دعوة المشرف فقط.

## 4. إعداد البيانات والمراجعة

- أنشئ دورة و8 محاضرات من لوحة الإدارة، ثم أضف النحو أو الصرف والمواعيد الحقيقية.
- انشر الدورة والموعد بعد المراجعة؛ لا ننشر مواعيد نموذجية على أنها مؤكدة.
- أدخل تكلفة الدورة الإجمالية وعدد الطلاب النشطين، وراجع أن مبلغ الطالب = الإجمالي / عدد الطلاب النشطين.
- لا تنقل بيانات تجريبية أو بيانات محلية من جهاز آخر دون مراجعة المصدر.

## 5. التحويل النهائي

- راجع Cloudflare Pages وSupabase أولًا، بما في ذلك الموبايل وتسجيل الدخول والقراءة العامة والحظر الخاص.
- حوّل مستودع GitHub إلى Private بعد تأكيد تشغيل Cloudflare من نسخته الأصلية وربطه بالمستودع الخاص.
- حدّث روابط المشاركة إلى Cloudflare Pages.
- لا توقف GitHub Pages قبل اختبار البديل، وعند تحويل المستودع إلى Private على GitHub Free قد يتوقف Pages القديم.

## اعتبارات الأمان

- المستودع الخاص لا يجعل JavaScript الذي يصل إلى متصفح المستخدم خاصًا. RLS هو الحماية الحقيقية للبيانات.
- `site_admins` لا يسمح إلا بقراءة سجل العضوية الخاص بالمستخدم؛ لا يمكن للمستخدمين إضافته أو تعديله.
- `students`, `enrollments`, `course_finances`, `payments` لا تسمح بقراءة مجهولة.
- محتوى `lessons.notes` ملاحظة عامة ولا يصلح لمعلومات سرية؛ لأن السجلات المنشورة تُعرض للزوار.
- بيانات كلمة مرور الطلاب أو رموز الدفع أو مفاتيح الوصول لا تخزن في الموقع.
